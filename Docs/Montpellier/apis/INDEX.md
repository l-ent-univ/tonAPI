# Index des endpoints HTTP — Université de Montpellier et IUT de Béziers

> Index consolidé de **tous** les endpoints HTTP documentés dans `Docs/Montpellier/` (fichiers principaux + `research/`). Généré le 2026-10-13 à partir des seuls faits écrits dans ces fichiers : rien n'est inventé, aucun secret ni donnée personnelle (placeholders `<…>`).
> Chaque ligne renvoie à la doc détaillée (colonne **Source**). Quand deux fichiers se contredisent, les deux versions figurent avec leur marque.

## Légende

| Colonne | Valeurs |
|---|---|
| **Méthode** | `GET`, `POST`, `DELETE`, `GET/POST` (indifférent), `WS` (fonction web service appelée via un endpoint générique), `SOAP` |
| **URL** | hôte + chemin ; placeholders `<…>` ; `<S>` = URL du service CAS final, `<md5>` = `md5(S sans query)`, `<ST>` = service ticket, `<uid>` = identifiant UM (`e` + 11 chiffres), `<hash>` = `userHash` ESUP-OTP, `<nip>` = n° étudiant |
| **Auth** | `aucune` · `cookie X` (cookie de session nommé) · `CAS UM` (chaîne CAS `cas.umontpellier.fr`, 2FA possible) · `CAS IUT` (`cas.iutbeziers.fr:8443`) · `jeton` (jeton/clé dans la requête) · `lien secret` (le jeton est dans l'URL) · `hash` (uid + `userHash` ESUP-OTP) · `api_password` / `compte technique` (inaccessible à tonAPI) |
| **Statut** | **[confirmé]** observé en direct (HAR, `curl`, navigateur connecté) · **[code]** lu dans un code source (client `lent-ios`/`tafac-ios`/`iCalFormater`, ou code serveur open source : esup-otp-api, esup-otp-cas-server, uPortal 4.3, Moodle 4.5, Passerelle ScoDoc, pyade) mais non observé à l'UM · **[déduit]** inféré d'un code ou d'une observation voisine · **[incertain]** hypothèse, non vérifié |
| **Source** | fichier et section de la doc d'origine (lien relatif) |

Règles transverses rappelées par les docs : un seul cookie jar par utilisateur, redirections suivies à la main (≤ 15 sauts), **un seul POST du mot de passe par tentative**, jamais de retry sur 5xx, logs masqués (`password`, `ticket`, `TGC`, `execution`, `data=`, `sesskey`, `wstoken`, `userHash`, `ZM_AUTH_TOKEN`, `preauth`…).

## Parcours minimal tonAPI (15 lignes)

1. **Login** — `GET https://ent.umontpellier.fr/uPortal/Login?refUrl=%2FuPortal%2F` → suivre les 302 jusqu'au `200` de `GET https://cas.umontpellier.fr/pre-otp/login?service=<enc(/cas/login-<md5>?service=<S>&auth_checked)>` ; lire `execution`.
2. `POST https://cas.umontpellier.fr/pre-otp/login?service=…` (même URL, query comprise) corps `username, password, execution, _eventId=submit, geolocation=, deviceFingerprint=<entier stable>` → 302 `+TGC` → `GET /cas/login-<md5>?…&ticket=<ST>` (`+connect.sid`).
3. **2FA** (si la réponse est un `200` « Authentification renforcée ») — lire `apiUrl, uid, userHash` dans `start({…})` et le `ticket` caché ; `GET https://otp-api.umontpellier.fr/users/<uid>/<hash>` (méthodes).
4. Ouvrir la socket **avant** le push : `GET https://otp-api.umontpellier.fr/sockets/?uid=<uid>&hash=<hash>&app=cas&EIO=4&transport=polling&t=<rand>` → `POST …&sid=<sid>` corps `40` ; puis `POST https://otp-api.umontpellier.fr/users/<uid>/methods/push/transports/push/<hash>?auto` ; poller `GET …&sid=` (répondre `3` à chaque `2`) jusqu'à `42["userAuth",{"code":"Ok","otp":"<6 chiffres>"}]` — ou prendre un code TOTP saisi.
5. `POST https://cas.umontpellier.fr/cas/login-<md5>?service=<S>` corps `ticket, uid_hint, token` → 302 `GET /cas/login?service=<S>` (page « Enregistrer l'appareil ») → `POST /cas/login?service=<S>&` corps `ticket, rememberMe=submit, rememberMeNoAsk=1` → suivre jusqu'à `/uPortal/f/<folderId>/normal/render.uP`. Garder **tous** les cookies `cas.umontpellier.fr`.
6. **Identité** — `GET https://ent.umontpellier.fr/uPortal/api/session.json` (`person.userName`, `displayName`) puis `GET /uPortal/api/people/<userName>.json` (`givenName`, `sn`, `mail`, `postalAddress`). Sonde de session : `GET /uPortal/layout.jsp?callback=x` (JSONP avec `user`) ou `session.json` (`userName != "guest"`).
7. **Emploi du temps** — `GET https://app.umontpellier.fr/prose-etudiant/protected/ical` (chaîne CAS silencieuse ; si `302 /prose-etudiant/invalidSession`, refaire le GET une fois) → regex `direct_cal\.jsp\?data=([0-9a-f]+),1` dans `var uidl`.
8. `GET https://proseconsult.umontpellier.fr/jsp/custom/modules/plannings/direct_cal.jsp?data=<256 hex>,1` **sans cookie** → `text/calendar` (lien déterministe, à stocker chiffré ; si HTML → relire l'étape 7).
9. **Notes + absences (IUT)** — `GET https://wscodoc.iutbeziers.fr/services/doAuth.php?href=https%3A%2F%2Fwscodoc.iutbeziers.fr%2F` → 302 `GET https://cas.iutbeziers.fr:8443/login?service=…` (200, lire `lt`, `service`) → `POST https://cas.iutbeziers.fr:8443/` corps `lt, service, username=<prenom.nom>, password` → 303 (GandiCert dans le bundle CA).
10. `GET …/doAuth.php?href=…&ticket=<ST>` → 302 → `GET …/doAuth.php?href=…` → 302 `https://wscodoc.iutbeziers.fr/` ; puis `POST https://wscodoc.iutbeziers.fr/services/data.php?q=dataPremi%C3%A8reConnexion` (cookie `PHPSESSID`) → `config, auth, semestres, relevé, absences, totauxAbsences`.
11. (option) `data.php?q=semestresEtudiant`, `data.php?q=relev%C3%A9Etudiant&semestre=<id>` (semestres passés), `data.php?q=getJustifs` ; `{"redirect":…}` = session expirée → refaire 9-10 une fois.
12. **Devoirs (IUT)** — `POST https://moodle-but.iutbeziers.fr/moodle/login/token.php` corps `username=<login UM>, password, service=moodle_mobile_app` → `{token, privatetoken}` (`invalidlogin` → 401, ne jamais réessayer automatiquement).
13. `POST https://moodle-but.iutbeziers.fr/moodle/webservice/rest/server.php` corps `wstoken, wsfunction, moodlewsrestformat=json` : `core_webservice_get_site_info` (une fois), `mod_assign_get_assignments`, `core_calendar_get_action_events_by_timesort(timesortfrom, limitnum=50)`, puis `mod_assign_get_submission_status(assignid)` par devoir restant (≤ 8 en parallèle) ; tester `errorcode` même en HTTP 200.
14. **Mail** — `GET https://mail.etu.umontpellier.fr/` → 302 `/public/preauthetu.jsp` → 302 CAS UM (**2FA souvent redemandée ici**) → `GET /public/preauthetu.jsp?ticket=<ST>` → 302 `/service/preauth/?account=…&preauth=…` → 302 `/mail` + cookie `ZM_AUTH_TOKEN` (≈ 12 h).
15. `GET https://mail.etu.umontpellier.fr/home/~/inbox.json` (cookie `ZM_AUTH_TOKEN`, `limit` ignoré) et/ou `POST /service/soap/GetFolderRequest` + `POST /service/soap/SearchRequest` (`authToken` dans `Header.context`, pot de cookies vide) ; `Fault AUTH_REQUIRED/AUTH_EXPIRED` → refaire 14 une fois.
