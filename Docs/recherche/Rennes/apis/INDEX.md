## Légende

| Colonne | Valeurs |
|---|---|
| **Méthode** | `GET`, `POST`, `ANY` (toute méthode), `AJAX` (fonction Moodle passée par `lib/ajax/service.php`), `GWT` (méthode GWT-RPC postée sur un service proxy) |
| **URL** | hôte + chemin ; `<S>` = URL de service CAS, `<ST>` = service ticket, `<p>` = `projectId` ADE, `<fname>` = identifiant de portlet, `<CAS>` = `https://sso-cas.univ-rennes.fr`, `<planning>` = `https://planning.univ-rennes.fr`, `<origin>` = origine Zimbra finale (`https://partage.univ-rennes1.fr`) |
| **Auth** | `aucune` · `TGC` (chaîne CAS silencieuse avec le cookie `TGC` de `sso-cas.univ-rennes.fr`) · `cookie X` (cookie de session nommé) · `Bearer` (jeton dans `Authorization`) · `SAML` (chaîne Shibboleth : SP → WAYF → IdP → CAS par TGC → POST SAML) · `sesskey` (session Moodle + `sesskey` en query) · `session tafac` (cookie `__Host-lent_session` du backend tafac) · `mot de passe` |
| **Statut** | **[code]** lu dans le code de tafac ou de lent-ios (fichier:ligne dans la doc source) · **[commit]** affirmé dans un message de commit tafac (vérifié par son auteur, pas par nous) · **[déduit]** conclusion tirée du code ou d'une observation voisine · **[incertain]** hypothèse, non vérifiée · **[confirmé]** (marque utilisée par `cas-rennes.md` et `ent.md`) vu dans une vraie réponse HTTP : GET publics sans identifiants du 14 oct. 2026 ou sonde anonyme du 29 sept. 2026 |
| **Source** | fichier et section de la doc d'origine (lien relatif) |

Règles transverses rappelées par les docs : **un seul cookie jar** par utilisateur qui suit toute la chaîne ENT → CAS → service ; redirections suivies **à la main** (15 sauts, 20 pour Partage, 25 pour Moodle) ; **ne pas réécrire la `Location`** du CAS ; **un seul POST du mot de passe** par tentative ; le mot de passe ne va **qu'au CAS** ; un 5xx n'est pas une déconnexion ; journaux masqués (`password`, `execution`, `ST-…`, `TGC`, `sesskey`, `SAMLResponse`, `ZM_AUTH_TOKEN`, `csrfToken`, `accessToken`, `refreshToken`, `refresh_token=`, nom du PDF de certificat).

## Parcours minimal tonAPI (15 appels)

1. **Login, entrée** — jar neuf ; `GET https://services-numeriques.univ-rennes.fr/f/services/normal/render.uP`, suivre à la main `/Login?refUrl=…` → `/api/cookiecheck` → `/Login?refUrl=…` → `render.uP` → `GET https://sso-cas.univ-rennes.fr/login?service=https://services-numeriques.univ-rennes.fr/Login%3FrefUrl%3D%2Ff%2Fservices%2Fnormal%2Frender.uP` (≈ 5 sauts, `Location` rejouée **telle quelle**) ; lire `execution`, `_eventId`, `geolocation` dans le `200`.
2. **Login, POST** — `POST` du formulaire (`username, password, execution, _eventId=submit, geolocation=` ; `deviceFingerprint` vide possible) sur l'URL de la page **avec** sa query (recommandation de `cas-rennes.md` ; tafac poste sur `/login` sans query et ça marche), `Origin`/`Referer` du CAS, `Accept-Language: fr-FR`. Classer : `302 …/Login?refUrl=…&ticket=<ST>` + `Set-Cookie TGC` = succès ; `200` avec `execution` = mauvais identifiants ; `200` avec `mfa-api.univ-rennes.fr` = **MFA** (page jamais capturée) ; 5xx/réseau = erreur technique.
3. Suivre `GET https://services-numeriques.univ-rennes.fr/Login?refUrl=%2Ff%2Fservices%2Fnormal%2Frender.uP&ticket=<ST>` → `302 render.uP` → `200`. Ne garder que le jar (surtout `TGC`), jamais le mot de passe.
4. **Preuve de session** — `GET https://services-numeriques.univ-rennes.fr/api/v4-3/dlm/layout.json` (`Accept: application/json`) : `authenticated == "true"` (**chaîne**), `user` = login Sésame. Sinon : rejouer l'étape 1 avec le seul TGC (après avoir vidé les cookies ENT).
5. **Identité** — `GET https://services-numeriques.univ-rennes.fr/api/v5-1/userinfo` (`Accept: application/jwt, application/json, */*`) → JWT (`exp = iat + 300 s`), claims `name`, `given_name`, `family_name`, `email`, `preferred_username` si présents [incertain sur les claims réels].
6. **Emploi du temps, jeton SSO** — `POST https://planning.univ-rennes.fr/portal/sso/accessToken` corps `{}` → `{token}` ; si vide/erreur : `GET https://sso-cas.univ-rennes.fr/login?service=https%3A%2F%2Fplanning.univ-rennes.fr%2Fportal%2F` (TGC → `302 /portal/?ticket=<ST>`), puis refaire le POST.
7. `POST https://planning.univ-rennes.fr/portal/RestApi/portal/ssologin` (`Authorization: Bearer <jeton SSO>`, corps `{}`) → `data.authData = {projectId, accessToken, refreshToken, resources[]}`.
8. (une fois, cache 30 min) `GET https://planning.univ-rennes.fr/portal/RestApi/portal/projects/<p>/resourcestree` (`Bearer <accessToken>`, `clientTimezone: Europe/Paris`, `Referer: …/portal/`) → arbre pour choisir niveau/TD/TP.
9. `GET https://planning.univ-rennes.fr/portal/RestApi/portal/projects/<p>/resourcesEventsPortal/resources;<ids>/startdate;<MMDDYYYY>/enddate;<MMDDYYYY>/level;=8/field;Nom;CODEZ_RESOURCE;OWNER;` → `data:[{id, events:[…]}]` ; sur `401` : `GET …/RestApi/portal/refreshtoken?refresh_token=<refreshToken>` (sans `Authorization`) puis **un** rejeu.
10. **Notes + absences (IUT de Lannion)** — `GET https://notes9.iutlan.univ-rennes1.fr/services/doAuth.php?href=https%3A%2F%2Fnotes9.iutlan.univ-rennes1.fr%2F` en suivant la chaîne avec le TGC (CAS → `doAuth.php?…&ticket=<ST>` → `/`), **un seul doAuth à la fois par utilisateur** ; si la chaîne s'arrête sur le formulaire CAS → 401 « session expirée ».
11. `GET https://notes9.iutlan.univ-rennes1.fr/services/data.php?q=dataPremi%C3%A8reConnexion` (`Accept: application/json`, `Referer: <origine>/`, cookie `PHPSESSID`) → `relevé` et/ou `semestres` ; `200 {"redirect":…}` → refaire 10 une fois. Les absences (`absences`, `totauxAbsences`) ne sont **pas lues** par tafac : clés supposées identiques à Béziers [incertain].
12. **Devoirs** — chaîne SAML sur une **copie** du jar : `GET https://foad.univ-rennes.fr/auth/shibboleth/index.php` → WAYF : `POST <action> user_idp=urn:mace:cru.fr:federation:univ-rennes1.fr&Select=Sélection` → IdP → `GET <CAS>/login?service=<IdP>` (TGC) → formulaire auto-soumis → `POST …/Shibboleth.sso/SAML2/POST` (`SAMLResponse`, `RelayState`) → `200 /my/` sans `notloggedin`, lire `"sesskey":"<…>"`.
13. `POST https://foad.univ-rennes.fr/lib/ajax/service.php?sesskey=<sesskey>&info=<m>` corps `[{"index":0,"methodname":"<m>","args":{…}}]`, en parallèle pour `core_calendar_get_action_events_by_timesort` (−7 j/+30 j, `limitnum:30`) et `core_calendar_get_calendar_upcoming_view` (`courseid:1, categoryid:0`) ; `errorcode` de session ⇒ refaire 12 une fois.
14. **Mail** — chaîne SAML sur une copie du jar : `GET https://partage.univ-rennes.fr/` → SP `sp.partage.renater.fr` → IdP → CAS (TGC) → POST SAML → `302 http://partage.univ-rennes1.fr/service/preauth?…` + `Set-Cookie ZM_AUTH_TOKEN` ; s'arrêter dès que le cookie existe et **forcer `https://`** sur l'origine.
15. `POST https://partage.univ-rennes1.fr/service/soap/SearchRequest` (`in:inbox`, `dateDesc`, `limit:5`) ∥ `POST …/service/soap/GetFolderRequest` (`folder:{l:"2"}`) en JSON avec le cookie `ZM_AUTH_TOKEN` ; si `SearchRequest` échoue : `GET …/service/home/~/inbox?fmt=json&limit=5` ; `AUTH_REQUIRED`/`AUTH_EXPIRED`/401 ⇒ refaire 14 une fois.

Déconnexion (hors parcours) : `GET https://services-numeriques.univ-rennes.fr/Logout` puis `GET https://sso-cas.univ-rennes.fr/logout`.
